# 干活方式（计划 / 机制优先 / 方向题 / 节奏）

> 2026-09-25 从 SKILL.md「子领域 · 方法论原则」逐条搬出，内容一条未删。
> 这一档管**怎么开工、先做什么**；具体工具与代码坑看 `cli-and-scripting.md`／`cli-authoring-pitfalls.md`。

---

### W1 · 长任务的第一件事是写计划

- **长任务的第一件事是写计划**（用户点名的默认动作，不是可选项）— 多阶段 / 跨文件 / 要跑好几轮的活，动手前先落计划书，四件套齐全：**阶段 · 产出 · 验收 · 卡点**，规矩是「验收不过不进下一阶段」。计划落到产出同处的目录（项目任务 → 项目目录；skill 自身改造 → skill 目录），每完成一项同步勾进度。**先干再补计划等于没有计划。** 见 `plan.md`


### W2 · 先摸机制，再动产出

- **先摸机制，再动产出**（2026-09-16 用户点名「很重要」）— 要新增/改一类东西，先把它的机制查到源头做实证（源码 / 官方文档 / 原始数据）再动手：机制清了多少，坑就少多少；凭印象直接产出 = 把坑埋进成品。配套工序：**机制实证 → 落工具（CLI/skill） → 小样验证 → 拿实测数字收敛 → 成线就拆**。世界书一线就是这么走的：先读引擎源码，逮到四个凭印象看不见的坑（二级键隐形门槛 / `order` 是全局排序键 / 卡内 book 级参数引擎不读 / `characterFilter` 只在独立书生效），随后才拆出 `bin/wb` + `sillytavern-worldbook`。**交付不带实测数字（token/条数/通过率）＝没交付，「写好了」不算。** 拆分形态见 `script-splitting-pattern.md`

- **机制判据要经「参数对照扫描」才算实证**（补 W2）——**↑ 判据已上提 「AGENTS.md」 〇节「判据要经参数对照」；本档留案例与实测。** 读一个接口／系统的行为时，别拿一两次调用就归纳出「哪个参数有效、哪条路走不通」。做法：**把可疑参数逐个扫一遍、对照每次返回的切片**（例：同一分页端点先固定小 `limit` 递增 `page`，再单独递增 `limit`，才看得出「`page` 有效但服务端偏一页」「大 `limit` 会跳过开头」——先前凭两次观察写下的「`page` 无效」是反的，改对后同一批数据从 39 条补到 61 条）。**判据写错比不写更糟**：错的机制会被后来的会话当事实照用，还会把没取全的写成「已取全」。2026-10-08 又一例：拿一次 `private:true` 建仓的 403 就断定「这把 token 不能建仓」（真相：public 能建、private 才被拒）。
- **发现机制写错就改写那一句本身**，不要原地补一条「已更正／UPDATE：其实是……」——补丁句会被读成「两种说法并存」，两个会话各信一边。
- **用户给的缩写／标准名先定位出处，别按字面猜。** 「按 X 的思路做」里的 X 可能是某份公开标准、某个实现里的机制、或他自己起的名。顺序：本地库全文搜（skill／档案／源码快照，连缩写大小写一起搜）→ 联网确认是哪一版 → 本地快照比它旧就照最新文档对齐 → 仍对不上就挑**自己体系里最近似的权威实现**对齐，并在交付时用一句说清「对齐的是哪一份；若你指另一份，给链接再校」。**猜错的代价是整轮返工，说清对齐源的代价是一句话。**


### W3 · 方向题先答，别先侦查

- **方向题先答，别先侦查**（用户叫停原话「用不着这么麻烦」）— 用户问「接下来要干嘛／要不要继续做 X」这类**方向题**时，先把站位给出去（一句现状 + 推荐走法 + 一个真要他定调的问题），别先跑一串 grep／搜索／翻库：方向题要的是判断，不是调查报告。**判据：这次侦查会不会改变我要说的话？不会就别查**；只有答案确实取决于仓库现状（「还剩几张没做」这类）才查**一条**最关键的。产出型任务照旧「先摸机制再动产出」，两者不冲突——区别在问句要的是判断还是成品。

**例外：规模／必要性题要先量再答**（「有必要留这么多吗」「是不是太多了」「值不值得做这么大」）——这类问句的答案**本身就取决于现状**，先把判断丢出去反而是拍脑袋。量**三个能直接进结论的数**：① 存量分布（多少真的被调用过，零调用的有几个、是不是刚建的）② 固定成本（每轮要付的索引／加载量，换算成字符或 token）③ 体积构成（多少是数据资产，多少是逻辑）。答法不是「该砍」也不是「都该留」，而是**说清成本在哪、什么在起作用**，然后摆**两条具体的路＋自己的倾向**让他选——别先辩护、也别先承诺大砍。界线同上：**每个数都要直接进结论**，量了用不上的维度不要跑（堆数据 = 又一次调查报告）。

- **量「多大」时别拿行数当内容量** — 表格与清单每行一个条目，行数能撑到 240+ 而字符只有 6.8K；排序一律看**字符数**（`ls`／格式检查工具报的是字节，中文 ÷3 ≈ 字符感）。第二层判据是**节的性质**，不是总量：展开型（流程／判例／实测，一条判据配一段说明）可以搬；清单型／索引用表（收录范围、字段对照、标号索引 `N1`／`F5` 这类一行一条）是检索件不是内容，搬走反而拆散别处按标号引用的锚点。**同一个 6–8K 的量级，有的该拆、有的判不动手，差别就在这里。**


### W4 · 用户把力气往哪条线调，就先把那条线做成一轮可交付

- **用户把力气往哪条线调，就先把那条线做成一轮可交付** — 他常用一句短语纠方向（如「X 还是很重要的」）。此时别急着回到自己原本的推荐：按他点的那条线走完「查到源头 → 落成工具 → 更新文档」再回来谈别的。方向纠正优先于自己的优先级排序。


### W5 · 逐个来

- **逐个来** — **↑ 判据已上提 「AGENTS.md」 〇节「逐个来」**（2026-10-08 用户重申）。入库/校对/修改时一次只处理一个文件，不批处理。写完一个再下一个


### W6 · 发现问题即时修

- **发现问题即时修** — 假阳性、边界情况、降级逻辑残留——看到就修，别只打「⚠️ 待处理」标记留到以后。用户明确纠正过「真有问题要及时修」


### W7 · 计划与报告里的判据，动手那一刻重新落地一遍

- **据以动手的判据必须在动手那一刻重读来源，不能照写计划／报告时的印象执行** — **↑ 判据已上提 「AGENTS.md」 〇节「动手那一刻重读判据来源」**（2026-10-08 被绊：一次 403 的误判写进汇报，用户差点照着去手工建仓；连「今天哪些条被踩过」这个判断本身，用的也是印象）。 写的时候读过的材料，执行时会记岔；当时那次读取甚至可能根本没成功（工具调用中断、输出没回来）而报告里已经写成了结论。**判据错一次，改法就整个反了。**实测两次反转：一组「两份是同主题双份」的判定，动手前重读原文才发现一份是**方法论**、一份是**工具手册**（互补不重复，只能并进门、不能当重复删）；另一组「上游／下游两道工序」的判定，重读后才发现是**同一套流程存了两份**（该并进宿主已有的那份 ref，而不是新建第二档）。两次都是「动手前重读」才拓回来。
- **自己写的报告同样不作准** — 报告是给人看的账目，不是可执行依据。凡「按报告里第几条去改」的动作，先读那一条的原始来源；报告里带细节的结论（判据、分类、去向）多是自己转述的，转述会漂。
- **工具生成的工作单也不作准**（补 W7）— 脚本吐出的「待办清单／工作单」是**分类逻辑的输出**：误报会和真实缺口混在一起，而且每条长得一模一样、看起来最像事实，所以最容易照单执行。做法：**动手前抽 1–2 条对着源头独立核一遍**（拿另一条命令查同一对象）。凡是①查询键与库主键形态不一致（短名查带前缀／后缀的全名）②「取不到」与「对不上」共用一条分支的逻辑，都会把**已完成的条目判成待办**。实测一份「要建档 12 个」的工作单，抽查前两条就发现 10 个早有档（查询用短名，档名是带消歧义后缀的全名，唯一候选被「防歧义」的保守规则吃掉返回 None）——照单执行就是白建＋重复。**不符就先修生成逻辑，再干活**；修完重跑，账目会自己缩到真缺口。「先干起来、边干边发现重复」比这贵得多，而且工具报的错数字会顺着汇报传出去。
- **体检工具的「问题总数」既不是工作量也不是真缺口**（补 W7）——格式／链接体检报出的数是**工具口径的产物**：同一批文档，`mdcheck` 报「引用不存在 1450」，`fix_md_links` 报「断链 1404」，两个都对、都不是待修量。写计划前先按**成因分四栏**：库内有同名文件（路径基准写错，可机械修）／全库查无（真断，人工）／跨库或模板占位（合法，不算）／重名（人工）。四栏加起来才对得上总引用数（实测 7739）。**按总数估工时的计划必然写歪**：可修量可能比报告数还大（工具保守跳过的部分），真问题量可能不到一半——两类偏差同时存在，不是取个中。


### W8 · 短指令拿不准，先对档再问

- **用户的短指令几乎都有前例，别急着反问** — 「下一步是这里」这类短句＝**接着做，方向你自己挑**（历史上它后面跟的就是自己挑的那一步）。含义靠上下文定，猜容易偏、问又白磨一轮。做法：用 `search_files` 到 `archive/session-archive/<月>.md` 里 grep 这句话的**全部历史出现**，看每次它前面是哪句请示、后面接了什么动作——两三处就能归纳出稳定用法。
- **判据**：历史里出现 ≥2 次且后续动作一致 ⇒ 按归纳执行；只出现一次、或后续动作互相矛盾 ⇒ 这时才问，且只问一个问题（把候选列出来让他挑）。**顺序是先对档再问，不是先问再对档。**


### W9 · 递来的「别人家的成品」先判类，再核现成

- **材料里的成品＝可能是需求，不只是素材** — 用户递来的记录／材料里夹着「别人做的同类成品」（一块状态面板、一个看板、一张界面截图）时，它默认多解：**素材**（读它、归档它）还是**需求暗示**（「你也整一个」）。判据：他随后会不会补一句「原本让你考虑的是这玩意」——会。做法：读完材料**先用一句话复述你打算做的事**（「这事我理解成：你要我也做一块？」）再动手；连错两轮（先当素材归档、再按自己的理解做成别的东西）比多问一句贵得多。
- **自建之前先核现成，别重造轮子** — 要做的东西多半已经有人做了一半：Hermes 自带 CLI（`hermes status --all` 出环境／网关／作业／会话，`hermes insights` 出 token·费用·工具·趋势）、已有的 `bin/` 工具、内置扩展点（dashboard 页签／TUI widget／插件 hook）。**先跑一遍并记下它的口径与耗时**：能用就复用、只补它没有的那截；从零写一套统计＋渲染，就是把「以创造接口重造轮子为耻」犯在自己身上。现成工具跑不动时把它记成缺口，别拿自算口径冒充同一个数。
- **「现成」也包括本库 skill 里已有的配方与命令片段**（补 W9）— 判「有没有人做过」时别只搜 `bin/` 与内置扩展点：**先 grep 整个 skills/ 库**（`grep -rln "<关键词>" skills/*/SKILL.md skills/*/references/`），而命中列表**要点开那条读内容**——按文件名猜相关性会把配方整个漏掉（实测：本机没有 unrar/7z 时从头摸了一遍 RAR 解压，而 `external-toolkit-onboarding` 的「列清单＋解压」节里早写着同一个配方，grep 命中过它、却因为标题像「收编工具包」被当成不相关跳过）。**环境/依赖类的新问题，先翻 skill 再动手**；按主题词搜不到就换词再搜一轮（工具名／文件扩展名／报错原文）。
- **被判「你自己应该看得出来问题在哪」时，停止猜** — 用户的纠偏常常只有一句结论（「思路搞错了」「应该能自己看出来」）而不给方位。此时的动作是**回一手源**（源码／接口／自己刚交的那份产物）**把候选问题列成带证据的清单**，一次摊开让他点，并**标出自己押的那条**（「我押第一条」）——继续在自己设想的那一层改表述、改字段，只会换来第三次同样的判语。**信号：同一件事被连纠两次 ＝ 前两轮都在错的层上迭代**（实测两轮分别停在「换文体」与「换字段」，真问题在产物的形态／外观）。改对之后把这条判断写回对应 skill，别只改产物。


### W10 · 「适配」＝接进链路，不是交一个能跑的工具

- **判据**（2026-11-14 用户原话「那就是还没做好适配」）：新能力接完，要能在**现有链路里当默认入口直接跑**——一条命令、自己决定用哪条通道、失败有降级。**只交独立 CLI／探针／对照表，用户会判「还没做好适配」**：那只是零件，选择权还在用的人手里。正确形态：统一入口（如 `doc2md`）包住原子工具（`pymupdf` 直取／`ds-ocr` 原始通道），按输入逐页分诊，异常自己补抓、补不动才报。
- 验收不是「跑通了」，而是**在真实输入上跑过**：真文件（不是只跑自己造的样例）、批量、耗时与费用都记一笔。自己跑过的测试只能证明「能跑」，说「好用」要等它在真实活里被用过一次——没用到就别自己发合格证。
