# CLI 落地踩坑 · 给本环境的脚本工程细节

> 2026-08-02 一口气做了 6 个 CLI（am_tool_gen / ro / meme / tts / hygiene / story）踩出来的。
> 适用：任何往 `skills/<name>/scripts/` 或 `<数据根>/bin/` 加脚本的场景。

## 1. bash 包装器必须显式处理 `--help`

`<数据根>/bin/tts` 第一版把 `--help` 当文本拿去合成语音了（edge-tts 收到 "usage: edge-tts..." 当正文朗读）。
bash 包装不会自动识别 `--help`——参数循环里必须自己加分支：

```bash
for a in "$@"; do
  case "$a" in
    --help|-h) echo "用法: ..."; exit 0 ;;
    *) ARGS+=("$a") ;;
  esac
done
```

**验证：** 每个 bash 包装写完跑一遍 `bin/xxx --help`，确认出的是用法不是执行动作。

## 2. list/search 类 CLI 必须处理 BrokenPipe

`meme list | head` 管道关闭时 py 直接抛 BrokenPipeError（Traceback 噪音）。加：

```python
import signal, sys
signal.signal(signal.SIGPIPE, signal.SIG_DFL)  # 管道关闭静默退出
```

**验证：** 写完 `xxx list | head -3`，确认无 Traceback。

## 3. HTML 去标签：块级标签先转行再删

strip_html 第一版把 `<p>` 直接删掉 → 段落全黏成一行（"标题测试第一段 & 内容第二段"）。
正确顺序：**先**把块级标签（p/div/br/li/ul/ol/tr/table/h1-6/section/article/blockquote）替换成 `\n`，**再**删其余标签：

```python
text = re.sub(r"</?(?:p|div|br|li|ul|ol|tr|table|h[1-6]|section|article|blockquote)[^>]*>", "\n", text, flags=re.IGNORECASE)
text = re.sub(r"<[^>]+>", "", text)
```

**验证：** 拿含多段的 HTML 片段测，确认段落间有换行。

## 4. gitignore 审计：裸 `references/` 危险，`/references/` 正确

判断通配泄漏时注意前导斜杠语义：
- 裸 `references/` → 匹配**任意层级**的 references 目录（会吞 skills/*/references/）→ 危险
- `/references/` → 锚定根目录 → **正确写法，不算问题**

```python
suspicious = [l for l in lines if l == "references/" and not l.startswith("/")]
```

第一版没判前导斜杠，把正确写法误报了。

## 5. SKILL.md 里写的路径可能是「应然」不是「实然」

某连载 skill 的 SKILL.md 写存档在 `<数据根>/archive/bili-articles/articles/2026/`——实际该目录不存在（B站专栏文章只有视频档）。
写脚本前先 `search_files` 验证文档路径是否真实存在；文档路径有规范价值就按文档建（story.py 就是按 SKILL.md 规范建的目录），但要意识到建出来的是新目录不是补已有目录。

## 6. 模板占位符替换后要 grep 验证

am_tool_gen.py 生成骨架后 `grep -c "{{"` 应返回 0——占位符全替换干净才交付。模板里别用 `{{TITLE}}` 之外的双花括号（会和 Jinja 风格混淆）。

## 7. write_file/patch 会跟 symlink 写「真实文件」——覆盖前先 rm symlink

`<数据根>/.npm-global/bin/mmx` 这类 npm bin 是 symlink（→ `../lib/node_modules/xxx/dist/xxx.mjs`）。
**write_file 不会写 symlink 本身，而是跟着指针直接写进真实目标文件**——2026-08-09 差点把 158KB 的 mmx-cli 官方入口覆盖成 1.5KB wrapper，靠 `npm install -g mmx-cli@1.0.18 --registry=https://registry.npmmirror.com` 重装找回（装完验证 md5 与原始一致）。

**规则**：任何要「用文件替换 symlink」的场景，顺序必须是：
1. `rm <数据根>/.npm-global/bin/mmx`（先删 symlink）
2. `write_file` 到 bin 路径（这次才是真建文件）
3. `chmod +x`

**判断文件是不是 symlink**：`ls -la` 看开头是不是 `l`（`lrwxrwxrwx ... -> 目标`）。npm 全局 bin、`/usr/bin` 里很多都是。

## 8. 子命令黑名单闸门：wrapper 替换 bin + 透传 + 提醒消息

要「杜绝某 CLI 的某些子命令」时（如 mmx 生图/图生图额度禁令），用 wrapper 替换 bin，不 patch dist 源码：

```js
// 骨架（node）：拦截规则匹配 cmd+sub，命中输出提醒消息 exit 2；其余透传
const MMX_REAL = '<数据根>/.npm-global/lib/node_modules/mmx-cli/dist/mmx.mjs';
for (const b of BLOCKED) if (b.match(cmd, sub)) { console.error(b.msg); process.exit(2); }
execFileSync(process.execPath, [MMX_REAL, ...args], { stdio: 'inherit' });
```

要点：
- **原文件不动**，wrapper 内部 exec 真实 CLI 绝对路径（源码还在原处，可随时绕过/恢复）
- 拦截规则按 `argv[0]+argv[1]`（cmd/sub）匹配，别只看 argv[0]（`image` 整个拦 vs `music` 只拦 `generate/cover`）
- 提醒消息写明「禁令 + 原因 + 日期 + 不执行」，别用假消息冒充成功
- **npm update / 重装会重建 symlink 覆盖 wrapper**——wrapper 源文件备份到 skill `scripts/`，SKILL.md 记重打步骤（rm symlink → 复制 → chmod）
- 交付验证：拦截命令输出提醒消息且 exit≠0；透传命令（help/quota/只读查询）全部正常

完整实战：mmx 三件套禁令闸门见一个姊妹 skill（未单独公开）（`references/mmx-voice.md` §二 + `scripts/mmx-wrapper.mjs`）。

## 9. 领域分类/篇名规则抽单一映射函数，别散落硬编码

`story.py` 原来把「过去篇」写死三处（正文档抬头 / INDEX 行 / link 正则），收到角色第 4 章（六章结构里属「外传篇」）就全错。
修法：`part_label(num)` 按编号映射（1~3 主线篇 / 4 外传篇 / 5 番外篇 / 6 最终章），三处统一调用。

**教训**：CLI 若涉及用户确认过的、会随数据推进的分类规则（章节归属/篇名/状态机），分类逻辑必须**单点定义**（映射函数或常量表），所有拼装处引用同一来源——别在模板字符串里复制规则。硬编码一次能跑，数据跨过边界就炸，而且三处一起错时很难看出是同一个根因。

## 10. 登记表备注清理：白名单（保留人工）优于黑名单（删自动）

`refresh_register` 原用「不含『正文已收档』」黑名单过滤旧段——旧进度段「**01~03 已收档**」不含那四字被当人工提示保留，与新进度叠成矛盾串（同一行一边说 04 待提供、一边说 04 已收）。
修法：改成**白名单**——只保留含「疑缺」的永久人工提示（现状全表此类就三种），其余段全量由文件系统实况重建。

**教训**：自动进度与人工提示混排的重写逻辑，清理旧自动段用「识别保留」（白名单，关键字=人工提示特征），**别用「识别删除」（黑名单）**——旧自动段的格式变体你永远猜不全（今天写「正文已收档」，昨天可能是「已收档」），黑名单必漏，漏了就是新旧矛盾叠加。

## 11. 向排序表插行：插完重排，别「永远插表头后」

`add_index_row` 每次插在表头分隔行后 → `stories/INDEX.md` 变 04,03,01,02 乱序（link 功能不受影响但表没法看）。
修法：插入后对整个表按（角色,编号）排序（`_sort_index_rows`，正则解析行内 key 后 `body.sort` 重组）。

**教训**：凡表格有隐含顺序（编号/日期/字母），插入逻辑必须维护顺序——要么按 key 找插入位，要么插完重排。「永远插顶部最省事」只在**追加型**（无自然序）的表成立；有编号/日期的表这样插三五行就乱。

## 12. dry-run 别落盘正式路径，否则污染下次 diff 基线

`<作品>-sync --dry-run` 先把 `characters-api-<date>.json` 存进正式 `data/` → 紧接着正式跑 diff 时「旧快照」= 自己刚 dry 出来的那份，diff 永远「无变化」（还白 commit 一份空快照，要 reset 回退）。
修法：dry-run 只抓取打印条数**不落盘**（`do_fetch(dry=True)` 提前 return）。

**教训**：带快照/diff 的 CLI，dry-run 模式必须不写正式产物（或写临时目录）。「演练不写盘」是 dry-run 的语义约定——落盘一次就毁掉下一次正式跑的对比基线。

## 13. 输出按「调用者要照抄的那段话」设计——别让调用者现算

扫雷裁判 CLI（`chat-game-referee/scripts/minesweeper.py`）原来只吐盘面：回话里的「未翻 N 格 / 剩余空格 / 旗 M 面」全靠现场心算，哈希复算也手写——两处都出过错（漏数旗格报错格数；摊牌把 5 颗雷全画 💥 被读成「踩雷输了」）。改法：盘面自带统计行（`未翻 N（含旗 M）｜剩余空格 K｜雷 L`）、`reveal` 直接打「独立复算 … → 一致 ✓」、摊牌附图例——回话里每个数字都能照抄。

**判断信号**：回话/报告里只要有任一处是「自己掰手指算的」，就该把它变成 CLI 的一行输出。调用者（自己自己、或另一个 agent）是 CLI 的用户，输出要按「抄下来就能用」的形态设计，而不是只给原始数据让它二次加工。

**边界**：CLI 出**事实**（盘面/计数/校验结果），不出**话术**——该怎么说、给不给提示仍由调用者判断；把「答案」印进输出是另一类事故（裁判场景尤其）。

**顺手化的四条设计标准**（同一原则被点过两次，已是默认要求）：调用成本 = **调用者敲了几条命令**，设计时按这四条量：

1. **同一件事一次跑完，分块不分次** —— 一次运行同时打「给人照贴的块」和「调用者自用的行」，两块用醒目标记分开（`── 发群（以下整块照贴）` … `── 发群到此`，末行 `自己手牌（暗牌，别贴进群）：…`）。反例：暗牌原来得补跑一次 `show --player` 去挑可贴的半边——同一手牌跑两趟，纯属白敲。
2. **固定收尾子命令化** —— 存档 / 生成文档 / 重建索引 / 记台账 / 打出提交命令，打成一条 `close`。别每次手工 cp + 手写 md + 手改 INDEX + 手敲台账。
3. **派生索引从唯一事实源重建** —— 存档文件里埋机器可读元数据（如 `<!-- meta {…} -->`），索引由脚本扫存档重建。手写的索引下一次就被冲掉，于是也没人会去手改；存档 = 唯一事实源，索引 = 派生物。
4. **防呆由 CLI 承担，别指望调用者记性好** —— 状态没到就挡（没收桌不许存档）、同一件事重做要挡（落戳记已处理）、同名产物自动加尾号别互盖。这三样都得写进代码，写进文档没用。

自检问句：**「自己要敲几次才能干完这件事？」答案超过一次就再想想。**

## 14. CLI 调兄弟 CLI：路径要备降级，顶层选项要放子命令前

一个子命令内部去调同目录的另一个 CLI（如 `close` 调 `ledger.py` 记台账）时，两处必踩：

- **兄弟脚本按「同级」解析，但先问那份副本为什么存在**：`os.path.join(os.path.dirname(os.path.abspath(__file__)), "ledger.py")` 就够——**别退到绝对路径**。老写法要备降级，是因为脚本有一份**部署副本**（`temp/<名>.py`），从副本跑时同目录没有兄弟。正解不是把候选表加长，而是**问那句「副本是为了解决什么」**：多数副本只是为了让状态落到某个目录——把状态根参数化（`$<工具>_HOME` ＞ 往上找带标志目录（`temp/`｜`workspace/`）的一层 ＞ 脚本上一级）之后副本就没必要存在，副本一消失，「从副本跑找不到兄弟」和「副本漂移」一整类坑跟着消失。
  - **代价**：把脚本**拷走单跑**的一方（自测的临时副本、别人 clone）必须**连兄弟脚本一起拷**——只拷主脚本那一份，失败会伪装成「台账没记上」而不是「脚本缺失」：自测红在断言里，不在加载时。
  - 真找不到还要降级打印一句说明（「台账：找不到 ledger.py，跳过（存档已落）」），别静默失败、也别让整条命令崩掉。

## 15. 散装脚本收「统一入口」：入口只分发，引擎不合并

`bin/<tool>`（一个入口 + 子命令）收掉一堆同族脚本时：

1. **入口只做分发** —— `SUBS = {子命令: 脚本名}` + `subprocess.call([python, script] + argv[1:])`，参数**原样透传**、退出码原样返回；**引擎一个都不合并**（合成一个文件 = 加一样东西就要重测全部，且多文件拷贝场景必漏拷）。旧命令（`python3 scripts/<x>.py …`）照旧能跑，入口只是多一条更短的路。
2. **`-h` 由入口兜底**：老脚本若是**手写 argv 解析**（不用 argparse），`xxx -h` 会被当默认动作**真跑出去**（扫雷会把盘面直接打出来）。入口见 `-h/--help` 且该脚本在手写名单里时，用 `ast.get_docstring` 读它的模块 docstring 当用法——别为了探测 help 去执行它；argparse 系的直接透传。
3. **名字对不上就别装作有**：跨目录/跨 skill 的子命令（入口里的 `spy` 指向兄弟 skill 的脚本）解析不到时，打一句「在 X 里，单跑本件时没有它」并非零退出——别留一个会静默失败的入口。
4. **给一条「列子命令」的路**（`<tool> list` ／ 无参数出用法），让「现在有哪些子命令、各自落在哪个文件」一眼可见，省得下个会话翻目录。

**改造验收（缺一不可）**：① 新入口一条子命令端到端（`--help` 不算）② 旧命令仍能跑 ③ **换个空的数据根实跑一次**（新建根 → 落盘函数少了 `makedirs` 就是第一盘直接崩）④ 全部自测。
- **子命令 CLIs 的顶层选项必须排在子命令之前**：`--ledger` 定义在主 parser 上时，`ledger.py add … --ledger X` 报 `unrecognized arguments`，正解是 `ledger.py --ledger X add …`。**调兄弟 CLI 前先 `--help` 看一眼选项挂在哪一层**，别照抄自己的参数顺序。
- **子进程一律 `subprocess.run([...], capture_output=True, text=True)`**：按 `returncode` 判断成功/降级，再决定回显什么。让它直接写终端的话，本 CLI 自己的审计/日志包装（Tee）也罩不住它的输出。

## 16. 数据根参数化之后：操作侧的三个坑

把状态/归档根做成可覆盖（`$<工具>_HOME` ＋ `--state`／`--archive`）之后，坑从「脚本怎么写」挪到了「用它的人怎么用」：

- **覆盖变量会静默换根，测完必须清**：`export GAME_HOME=/tmp/x` 之后再跑真命令，它会老老实实写到 `/tmp/x` 下并**打印成功**（实测：索引重建报「共 6 档」，真目录一个字节没动）。规矩：覆盖变量只活在单条命令里（`VAR=值 <cmd>`）；`export` 过的用完立刻 `unset`；验收真数据时**显式给 `--archive/--state`**，别依赖环境。
- **新产物跟着既有布局走，别在既有数据旁铺一套平行的**：老档在 `<根>/对局/` 子目录里、脚本默认平铺 `<根>/`，硬按默认走就是两套布局并存（下次分不清哪份是正主）。做法：落点函数先看既有子目录在不在（在就跟它），没有才用默认；读取端两种布局都认。
- **把人工手写的段并进生成器的尾巴**：切到「索引/清单由脚本重建」时，原文件里手写的流程说明、落款会被下一次重建冲掉。先把它搬进生成器的尾部模板（`INDEX_TAIL`）再重建——**生成物里的手写内容是事实源的一部分，不能只活在会被覆盖的那一份里**。

## 收编孤儿脚本进既有家族

同族已经有一套口径（数据根、承诺/自证、收桌存档、自测 Harness），而某散件脚本是「家族外的远亲」时——**只当玩法与规则的来源，按家族口径重写，不照搬**：

1. **先对口径再动手**：把散件的参数/机制逐条过一遍——① 从不生效的 flag（存下来但影响不了任何结果）直接删，留着就是骗读者「有这功能」；② 已被项目判死的机制（如「预设台词池」——聊天场景里有 agent 本人充当那个角色，池子没活干）不要因为散件里有就带回来；③ 状态/归档路径按家族数据根重做。
2. **拿家族里最接近的那份当模板**（代码块逐字照拄、承诺/收桌/INDEX 重建/自测 Harness 全跟着它），别自己发明第二套写法。
3. **既有数据用 backfill 过渡，不重建**：老档缺机器可读元数据（`<!-- meta -->`）时，先按旧格式解析回填，**源文本一个字不改**；扫描时同时认新旧两种写法（老档的提交记录是手写行，格式变体得容错），否则一升级就把真档读成空的。
4. **命名撞车要当场发现**：新子命令名先查家族入口已有的别名（`dice` 已给大话骰 → 掷骰只能走 `duel`）——别名冲突在入口层静默（敲 `dice` 进了别的游戏），必须在挂入口时就撞出来。

## 17. 子脚本里的 `input("按回车键退出...")`：非交互调用会每次吐一行垃圾

给「双击/终端直跑」加暂停提示时，常见写法是脚本结尾 `input("\n按回车键退出...")`。但**入口 CLI 用 `subprocess` 调子脚本时通常给 `stdin=DEVNULL`**（免得子脚本抢走父进程的 stdin）——此时 `input(prompt)` 会**先把提示写进 stdout，再去读 stdin，读到 EOF 才退出**：不是「多等一下」，而是**每次调用都往输出里刻一行提示**，把机读输出（报告、JSON、被父脚本解析的文本）一起污染掉。

修法（所有子脚本一次改掉）：

```python
try:
    if sys.stdin.isatty():      # 交互终端才等回车；管道/被父 CLI 调用直接退出
        input("\n按回车键退出...")
except EOFError:
    pass
```

- 判 `isatty()` 就够，不必再加开关：父入口给 DEVNULL → 非 TTY → 静默退出；人直接跑脚本 → TTY → 保留友好暂停。
- **改完加一条回归自检项**（跑一个子脚本、`stdin=DEVNULL`、断言 stdout+stderr 里没有那句提示）——否则下个人「为了双击友好」又加回去。
- 同类隐患：任何「为人类舒服」的交互副作用（进度条刷屏、ANSI 颜色、等待输入）放进子脚本前先问「被另一个程序调用时会怎样」。

## 18. 报告里别把「模拟算出来的数」和「跑出来的数」混排

覆盖率/健康度这类报告最容易埋的坑：把**模拟指标**（均匀随机采样 N 次的命中率、利用率、峰值比）和**真实运行数据**（日志里的命中/兜底占比）并排印在同一段，读者分不清哪个能信。

- **均匀采样下的「均匀性」类指标没有信息量**：随机撒点统计各格命中次数，结果必然≈均匀（平均次数、峰值比恒在 1 附近）——它测的是采样器不是数据本身，**长得像实测却什么都没测**。换成静态可算的真指标（如「变体密度」：平均条数 + 只有 1 条的格子数），才直接回答「哪里会很快重复」。
- **报告拆两段并标注口径**：【理论】按配置算、不依赖运行（模拟数字在括注里写明「模拟口径：均匀随机 N 次」）；【实测】从运行日志读真数据（命中/兜底占比、触达数、冷格子、高频 TOP）。
- **真实数据段要指向动作**：有兜底命中 → 提示去查日志定位有洞的位置；没有日志 → 明确说「还没跑过真实触发」并给出怎么跑的命令，别留空让人误读成「全零」。
- 通用问句：**这个数是「算出来的」还是「跑出来的」？** 混在一段等于把假设当结论。

## 19. 「读原文 → 追加 → 写回」必须分两行：`open(p,'w')` 先截断再给你读

```python
open(p,'w',encoding='utf-8').write(open(p,encoding='utf-8').read() + add)   # ✗ 读到的是空文件
```

求值顺序是**先把文件截断、再打开去读**——`read()` 返回空串，等于把整篇内容换成 `add`（实测：一篇 18KB 的记账文档当场被清空，靠 `git show HEAD:<路径>` 找回）。规矩：**同一个文件先读进变量、再开写**：

```python
t = open(p,encoding='utf-8').read()
open(p,'w',encoding='utf-8').write(t + add)
```

- 凡「读—改—写」同一路径（追加一节、改一行、回填数字、把人工段并进生成器尾巴），**读和写必须是两条独立语句**；纯追加就用 append 模式（`open(p,'a')`）。
- **写完立刻看一眼**：`git diff --stat <path>` 或 `wc -l` ——毁文件的那次写入同样会报成功，只有回读看得出来。

## 20. 查询类 CLI 的空结果必须「可自证」——空 ≠ 不存在

`xxx check <关键词>` / `xxx find` / `xxx search` 这类面向人的查询命令，匹配不到时只印一句「没有匹配」，**这句会被读成「这东西不存在」**；而真相常是「查法不对」（关键词用了译名／别名／简称，数据里存的是原名／编号）。实测：同一个库，译名查空、原名与 ID 查命中——一次误判被直接写进了档案结论。

规矩：空结果要把「为什么空」印出来，让人当场改关键词，而不是带着错误结论离开。

```python
if hits:
    ...
else:
    print(f'没有匹配 "{kw}"（共 {len(rows)} 条）')
    if any(ord(c) > 127 for c in kw):      # 非 ASCII 关键词：库里多半存的是原名
        print('  ⚠️ 关键词含非 ASCII——库里条目名多为原文名，译名会静默判「无」；改用原名或 ID 重查')
    # 相似候选：把候选名按词拆开比，别拿关键词跟整名比
    def _sim(cand):
        best = difflib.SequenceMatcher(None, kw, cand.lower()).ratio()
        for w in re.split(r'[\s:\-–_,.()\[\]!/]+', cand.lower()):
            if len(w) >= 3:
                best = max(best, difflib.SequenceMatcher(None, kw, w).ratio())
        return best
    for s, a, nm in sorted(((_sim(n), a, n) for a, n in parsed), key=lambda x: -x[0]):
        if s >= 0.72:
            print(f'    相近：{a}  {nm}')
```

- **别用 `difflib.get_close_matches(kw, 全名列表)`**：长名（带副标题／版本后缀）会把它淹没，返回一堆长度相近的噪声（实测：拼错的关键词返回了完全不相关的一批条目）；**按词拆开再比**才命中真目标。
- 纯数字关键词补一句「按 ID 精确匹配；这里没有就是没有」——把两种情况分开说。
- **推广**：任何「查询 → 给结论」的 CLI，空结果、零命中、样本不足属同一类——**必须区分「查不到」与「不存在」**，并给出下一步（换关键词／换源／加参数）。只印空结果的查询工具，用户会把它的失败当成世界的属性。
- **修完顺手扫同类结论**：拿同一个判据全库 grep 一遍已有的结论性描述（「未入／不在库／不存在」），逐条用硬标识符复核。写 pitfall 只能防下一次，扫存量才堵住已经流出去的错误结论。

## 21. 多通道抓取：默认走最便宜的那条，升级判据写进自检

同一个目标常有多条取数通道，成本差一个量级（实测：同一项目页 `curl` SSR ≈1 秒 ／ Playwright 渲染 ≈11 秒）。把最贵的那条写成默认，就是每条命令白等十秒；把最便宜的那条写成默认，又要防它取不全。

- **默认跑最便宜通道，用「结果自证」判够不够**：解析出目标字段（例：剥标签后搜得到 `已支持 N 份`）就收工，解析不出才升级到兜底通道；另给一个 `--render` 类开关供强制。
- **输出里每段标「数据从哪来」**（`档位实销（来源：SSR／渲染）`）：同一工具两条通道出的数，人一眼分得清，出问题时知道该怀疑哪条。
- **平台侧行为会变，所以「某通道拿不到 X」的结论要自带复查**：先例是「`curl` 只有骨架 → 必须渲染」，后来同一命令直出了全字段。默认快路径 ＋ 自检升级天然就是复查机制——平台哪天变回去，脚本自己跟上，不指望有人记得改默认值。
- **文档与脚本行为同步**：reference 里那句「必须渲染」是让人照着做的，改脚本时一并改掉，别留旧结论在文档里拉人走错路。

## 22. 生成「给人填的文件」之前，先读下游解析器的格式约定

生成器与解析器是一对契约，两边分开写必然对不上——**解析端的正则常把「有没有内容」编进格式**（`^\[([^\]]+)\]\s*(.+)$` 这种要求 `]` 后面必须有东西），而生成器只要少一个字符，整批占位行就被判成「无法识别」并掉进错误桶。

- **先读解析器源码**，把它的正则、跳过规则（注释行前缀）、容错分支抄下来当格式规格；别按自己顺手的形态写生成物。
- **中间态要有归宿**：生成的占位行（标了目标、还没填内容）必须在解析端**单独成一类**（如「空占位 N 条」），别让它掉进「未标注／无效标注」桶——「没填」与「填错了」是完全不同的两个信号。
- **收尾清理只去末尾空行，别对整串 `rstrip()`**：`"\n".join(L).rstrip()` 会连最后一行的**行尾空格一起吃掉**，而占位行常靠行尾空白表示「就在这儿填」。要收尾就 `while L and not L[-1].strip(): L.pop()`。
- **验收跑「生成 → 填 → 回灌」整条链**：光看生成物长得对不算——实测上一版就是在回灌那一步才暴露（占位行被当成「未标注」列出来）；且要分别试「填了」与「留着没填」两种行。
- **生成物自己声明身份**：固定文件名 + 头一行写「本文件由 X 生成 · 会被覆盖」，别让生成的临时行与用户手写的长久内容混在同一目录里靠猜（落点选在用户手写内容旁边时尤其要写明）。
- **反向同样要咬合：你的占位标记必须用下游判据认得的精确字面。** 占位本来就是给检查器抓的——差一个字符（写 `【需补充：说明】`，而判据查的是精确子串 `【需补充】`）就**静默通过**，得到「看起来干净、其实没填」，比明着报错更危险。动手前先读判据的实现（正则／子串／词表／黑名单），照它的字面原样拼；改完回头确认检查器**真的报出来了**——报出来才叫量得到，填完归零才叫做完。
- **下游有官方校验器就别自造验收**：能复用就调它的（产出酒馆卡就调卡 skill 自带的 validator `--deep`），格式合法性以它为准，自己写的「我检查过了」不算实证。跨工具引用做成**可选依赖**——按已知路径探测，找不到就跳过并如实说明「这台机器没装，未做该步验收」，别硬绑：读者装没装是读者的事。

## 23. 「不重复感」的选择器：别把严格优先级放在随机池前面

要求是「同一句短期不重复、顺序又不机械」时，最顺手的写法是「先取用得最少的那一批 → 再从里面挑」。但小池子里（3 条变体）那一批**永远只剩 1 个候选**——随机性被结构吃光，序列退化成 `A→B→C` 死循环，后加的冷却窗也永远轮不到生效（实测：以为加好了，跑出来跟改前一模一样）。

- **优先级用权重表达，不要用过滤表达**：冷却窗按池子自适应 `k = min(cooldown, n-2)`（至少留 2 个候选），再在剩下的里**按权重随机**（用得越少权重越大，`1/(1+count)`）——长期均衡与随机空间兼得。
- **断言要能测出「确定循环」**：只断言「无连续重复」测不出这个 bug——死循环本来就不连续重复。必须加一条 **「两次独立序列不同」**：同一格清状态后跑两趟，序列必须不一样；再补一条「n 次里每个变体都出现过」防饿死。
- **边界也要试**：单变体格（过滤后池子会是空 → 必须回退到全池、稳定返回不抛错）、空配置（返回占位文案不抛）。
- **泛化**：任何「按优先级挑一个」的自动选择器（推荐、轮换、抽签、调度），只要还有「别太机械」的要求，先问一句：**过滤条件在最坏情况下会不会把候选收到 1 个？** 会，就改用权重。

## 24. 改了生成器 ≠ 重新生成现有产物

调完生成器的模板或策略（如给引擎加状态层）之后，别顺手把**所有**已生成的产物重跑一遍——已经在生产里跑的那份，**没有明确需求就不动**：它的行为是一批调用方（定时任务、别的脚本）依赖的现状，重生成等于替它们做了一次没人要求的升级（实测：生产链路直接 import 那份生成物，动它就是动线上）。

- **只对示例／新建对象重生成**，并在报告里写明「现有产物不受影响，重新生成才生效」——把「生成器改了」与「产物要换」拆成两个决定。
- **消费方无论如何都要实跑一次**：哪怕它加载的是旧产物，确认这条路没被你改坏（生成器与产物解耦，改一边不等于改另一边）——改完跑一遍消费方自检 + 真跑一条，别只跑生成器自己的 `--selftest`。

### P3 · replace 模式补丁：`new_string` 里只放目标内容，写完立刻复核

- **replace 模式补丁：`new_string` 里只放目标内容，写完立刻复核（2026-09-14 实战）** — 把思路草稿、解释性散文、甚至工具调用 XML 一起塞进 `new_string`，会被**原样写进源文件**（整块重复 + SyntaxError，比改错锚点更难察觉）。写完立刻做两件事：① 语法自检（Python：`python3 -c "import ast;ast.parse(open(f,encoding='utf-8').read())"`）② `git diff` 扫一眼有没有非目标内容。**一旦写坏：`git checkout HEAD -- <文件>` 回到上一个干净提交再重打一次干净的补丁**——别在坏文件上继续补，越补越乱；有未提交的并行改动时先确认那文件本来就是干净的再回滚。


### P4 · 一次改多文件多处：用 execute_code 里的断言式 `edit(path

- **一次改多文件多处：用 execute_code 里的断言式 `edit(path, pairs)`，别逐处调 patch** — 一个文件改三五处、一批改六七个文件时，逐处 patch 既费往返又容易抄错上下文。写成 helper：读文件 → 逐对 `str.replace` → **每对先断言 `count == 1`**（不中就把命中数打出来、该文件不写回、返回 False），全对才落盘，末尾回显 `✅ <路径>`。一次调用跑完整批，失败清单一眼看清。

### P6 · 往文件末尾追加：锚点行必须原样包含进 `new_string`

- **把锚点行当分隔符用 = 当场吃掉那一行** — 追加一节的直觉写法是「拿最后一行当 `old_string`，`new_string` 只写新内容」，结果锚点行被整行替换掉（实测：往台账追加新一节时，同段上一行的「备用方案」当场消失，只有回读才看得见）。规矩：追加 = `old_string` 取锚点行、`new_string` = **锚点行原文 + 换行 + 新内容**；改完立刻 `git diff --stat <path>`，**删除数应为 0**（行只增不减）再 commit。
