# 单文件 HTML 小工具/小游戏

> 场景：要交一个「别人拿到就能跑」的东西——发群里、甩手机上、双击打开，不装环境不联网。
> 核心不是画面好看，是**一局能跑完、数值站得住、交付件和测过的那个字节一致**。

## 1. 形态选择

- **只有一个 HTML 文件**：CSS/JS 全内联，零外链（字体、图标、CDN 一律不用）。手机竖屏优先，`max-width:480px` 居中，点击目标 ≥44px。
- 游戏/工具状态全在内存，存档走 `localStorage`（用 try/catch 包住——file:// 下可能抛）。
- 一局 1–3 分钟。结果页要**能截图**：大数字 + 评级 + 一句评语 + 几个关键指标，这是群传播的载体，比玩法本身更重要。

## 2. 逻辑与界面分家（关键一步）

把纯逻辑整块包进标记注释，UI 只读它、不重写它：

```
// CORE-START 纯逻辑，不碰 DOM
var PROJECTS=[...], PLANS=[...];
function newRun(seed){...}   // 全部状态放进一个 state 对象
function step(s, action){...} // 返回 {ok, entries:[{t,cls}], gain, over, settlement}
// CORE-END
```

- **核心块里一行 DOM 都不许出现**，所有文案也从这里吐（`entries` 里带文本和样式类），UI 只负责 append。
- 切块给 node 跑时，按标记 `split` 后**补一个行首 `//`**——标记行后面常挂着说明文字，直接 eval 会语法错。
- **随机必须可注入**：用带种子的 PRNG（mulberry32 那种十几行），别用 `Math.random()`。否则同一局复盘不了、批量模拟没意义。
- 每次消耗 rng 的次数会改变后续序列——**改文案选择逻辑也会改变数值分布**，改完必须重跑模拟。

## 3. 数值先量后定档（最容易翻车的地方）

写个 `test_*.js`：切出核心块、N 个种子 × 几种典型策略各跑一遍，输出**分位数 + 各档占比 + 平均步数**。

要断言的不变量（缺一条就可能上线即废）：

- 不死循环（每次循环加 guard，超上限直接抛）
- 无 `NaN`／无负数资源
- 步数不超过上限
- 「结算对象」和「结束时状态」一致（金额、轮数逐项对）
- 只允许选**付得起**的选项——UI 置灰不算数，核心也得拒
- 策略兜底：策略想选的选项付不起时，退到可选项里，别让测试自己撞墙

**评级阈值不是拍脑袋定的，是从分布倒推的**：先跑出来看 p25 / 中位 / p75 / p99，再把 S/SSS 放在 p95–p99 之上、把及格线放在 p25 附近。第一版常数最常见的病是「人人满级」——这时候别调阈值糊过去，先问收益链是不是漏了衰减或风险。

改任何常数（成本、倍率、衰减、爆率）都重跑一遍再看分布；同时比对几种极端策略（全认真 / 全便宜 / 全赌博），三条路都要活着、且**风险越高方差越大**，否则选择就是假的。

## 4. 无头验收（逻辑对了不等于能用）

用 playwright 起手机视口跑完整局，至少两档（如 390×844 与 360×640）：

```python
pg = browser.new_page(viewport={"width":390,"height":844}, is_mobile=True, has_touch=True)
pg.on("console", lambda m: errs.append(m.text) if m.type=="error" else None)
pg.on("pageerror", lambda e: errs.append(str(e)))
```

点满一整局后断言：

- console / pageerror 零报错
- `document.documentElement.scrollWidth == clientWidth`（无横向溢出）
- 每个按钮 `rect.bottom < window.innerHeight`（小屏不把选项顶出屏幕）
- 结束态真的出现、重开按钮真的能重开
- 截图丢给视觉模型看一遍排版（它抓得住「半行文字被裁」「灰字对比度太低」这种人眼一眼过的东西）

**浏览器版本对不上时不要重装**：playwright 包会去找特定版本的 chromium，找不到就报 `Executable doesn't exist`。去浏览器缓存目录里 glob 已经下载好的 `chrome-headless-shell`，`launch(executable_path=...)` 指过去即可，比联网下载快且稳。

## 5. 交付一致性

- 改过显示名就用 `cp` 另存，**不要重写一份**；发之前 `md5sum` 两个文件对比，确认交付的就是测过的那个字节。
- 附件投递走 `bin/qqsend send <群> --attach <文件>`；**`-f` 和 `--attach` 一起用会丢正文**（见 `qq-group-intel` 同节）。
- 群里说明文字一律纯文本，别用 markdown 符号。

## 6. 文案

- 短句、带具体名词、结果分档写 2–3 个变体随机取——同一档位反复出同一句话，玩家第二局就麻了。
- 失败态要写得比成功态更好笑（「你自己都没敢点第二遍」比任何成就文案都传播）。
- 结算页留一句引导分享的话，但别喊口号，用角色口吻说。
