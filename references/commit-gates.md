## 提交门禁（把检查装到 git 上）


> 口径写在文档里＝靠记得；实测不到一轮就漏。把批量检查包成一条 CLI（`<tool> gate`），再挂 `.git/hooks/pre-commit`：只查暂存区里动过的目标文件（`--changed`），跑不过就**拒提交**，`git commit --no-verify` 当逃生口。

- **CLI 的退出码先查这一行**：Python 里 `main()` 的返回值默认被丢掉——脚本永远 exit 0，钩子变成**假拦**（违规样本照样提交成功）。写 `sys.exit(main() or 0)`；任何「返回值即成败」的 CLI 都适用。
- **暂存路径是仓库根相对**：`git -C <子目录> diff --cached --name-only` 仍返回**仓库根**相对路径——拼绝对路径要用 `git rev-parse --show-toplevel` 的结果；拿子目录去拼会得到双层前缀（FileNotFoundError，还会被当成「拦住了」，看不出真因）。
- **装完必须实测拦得住**：造一个违规样本 → `git add` → `git commit`，确认**退出码非 0 且提交未创建**。「脚本写好了」不算验证。
- **样本必须有内容差异，否则测的是空跑**：拿一份与 HEAD 逐字相同的文件 `git add`，暂存区是空的 → 钩子拿到的目标列表为空 → 直接放行，你会把「没测到」误读成「测过了」（回显利利一句「没有要查的目标，放行」）。每一轮验证都换新文件或至少改一个字节；修完 bug 重测同理。
- **拦截时要把「哪几条挂了」打到 stdout**：钩子里的输出用户会在 `git commit` 回显里直接看到——只报「未过」等于把复现成本推回给用户。每条检查打一行 `✅ 名称 实测值（阈值）`，结尾再给汇总（X/Y 通过、挂的清单、存量挂账清单）；「存量/增量」两类分开列，别让老账淹没真问题。
- **两套视图同源**：`<tool> gate`（全量，看现状与存量欠债）与 `gate --changed`（差异，给钩子用）共用同一段检查代码，只换「选哪些目标」——别写成两套逻辑，否则本地过、提交挂。
- **测完清理用 `git reset --mixed <上一条 sha>`**：`git reset` 不带参数**不会**撤销已提交内容，试探用的垃圾提交会留在历史里。
- **存量老账与新增违规分开放**：配置里分「放宽」（已记账的区间外阈值）与「暂缓」（本轮不修的老问题 → 显示 ⚠️ 但不卡门）——**存量挂着、增量堵死**；一视同仁地卡，第一天就会被历史欠债逼到只用 `--no-verify`。
- **即将被合入的目标要更严**：待替换的草稿／小样走同一套检查，且**不适用暂缓**——草稿带病合入，等于把病写进正式产物。另：草稿/样板往往是**旧口径时期**做的，合入时除跑当下全部门禁，还要**逐条看它接没接上上一批交给它的东西**——实测一版样板 `她说`×9、一版重做稿 `她说`×12，另有一处说话人标反（标签与内容打架，量尺和扫雷都抓不到），全是换入时逐句核才挖出来的。
- **阈值带按被测对象自己的实测分布定，不照抄别类样本的基线**：区间型阈值（占比／句长／比例）先在**本类产物的全量**上量一遍再定带，越界的少数再逐条登记放宽（写明原因）。照搬其它样本的基线，结果不是天天误报，就是把口径定成当时摸不到的天花板——实测：短篇基线搬到长篇，一半的节当场挂掉；改用本类实测分布后，只剩真该盯的那两三节。
- **从文档里抽「承诺」去核产物时，先限定在承诺列**：只从写着“要做什么”的那一栏抽词，排除「收在哪」这类**跨节引用**栏、版本日志、行号与纯数字。不筛的话假阳性会淹掉真问题（实测同一批文档：不筛 17–86 词 → 筛完 1–11 词，真的那几个才露出来）。
- **核对的定位是「承诺 vs 产物」，不是「笔记 vs 产物」**：台账里被引号／括号包起来的注记会被解析器当成承诺，报出一堆“产物里没有”的假账；而且**往台账里补新条目时也会踩同一坑**（把待办当成已实现的台词写进引号里）。台账写作规矩：**承诺列只写产物里真有的词，注记写成行内文字**（放到引号／括号外）。
- **收口 ＝ 门禁 PASS 且核对 0 遗留**：核对结果里的“待人工确认”**不许跨节／跨批次留**（用户原话：「有遗漏的点就要顺手处理下，不要留」）；本轮确实办不到的，才进配置的暂缓表并写明原因，换入新产物后重跑清账。
